Every call takes a fixed capacity string, and the capacity is spelled out in the method name. That looks like bad taste until you remember the constraint: compiled fast code cannot build a managed string at all, because building one means allocating. A fixed capacity string is a value type with its bytes inline, so it can be assembled on the stack. The capacity has to be in the name because it is part of the type. And the verbose and debug levels are compiled out entirely rather than filtered at runtime, so an unused log line costs literally nothing in a shipped build.
