This one caught me out. There is no runtime system that reads an attribute and decides which world a settings asset belongs in. The attribute is read in the editor, when the asset is created, and the editor writes that asset into the array on a particular prefab. By the time you press play the decision is already baked into a scene. So if a settings entity is in the wrong world, the bug is not in a system anywhere; it is in which prefab that asset was written onto, months ago.
