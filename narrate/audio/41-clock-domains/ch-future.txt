Now the other side, and this one you have definitely built before, in silicon. A predicted entity is simulated ahead of the server, on the client's own timeline. Every frame it restores that entity to the last tick the server confirmed, then resimulates every tick from there up to the present. Each arriving snapshot is a checkpoint. It either agrees, in which case the restore changes nothing, or it disagrees, and the replay lands somewhere different. That is speculative execution with a pipeline flush, right down to the cost model.
