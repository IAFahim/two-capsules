The predicted physics world can only contain things that roll back, so a dynamic body that is not a ghost is an error. If you want ragdolls, debris or cosmetic impacts, and in a physics heavy game you will, they have to leave the default index. Set the non ghost world index in the netcode physics config, give the prefabs a matching index, and the validation system stops complaining while the predicted world stays small. The config is baked from a component in a subscene, and when it is absent the rate manager falls through to a default initialised struct, which is enum value zero, which is the narrowest of the three run modes. No config is not everything on. It is the most restrictive gate.
