Open the physics package and search it for world filter attributes. The runtime has none. The only ones in the whole package are on baking systems and debug display systems. The physics group carries exactly one attribute, saying which group it updates in, and nothing about where it is allowed to exist. That silence is the answer to the question. An unfiltered system resolves to the default flag, the default flag is replaced by the parent group's child default, and a chain that ends at the root simulation group falls through to a hard coded fallback: local, server and client simulation. So the solver runs in the single player world, the client world and the server world. It does not run in a thin client.
