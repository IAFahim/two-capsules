Physics normally runs in the fixed step group, driven by an accumulator against wall clock time. That is the wrong clock for prediction, because prediction needs to run the same tick several times. So netcode moves it, on the client and on the server both. The move is a transitive closure, not a list: it seeds a set with the physics group, then repeatedly scans the fixed step group adding any system whose ordering attributes name something already in the set, looping until a full pass adds nothing. Think of it as a clock domain crossing. The logic is untouched. Only the clock feeding it is swapped, from a wall clock at one edge per frame to a prediction tick that can issue many edges in a single frame.
