The first thing that happens is not encoding. It is sorting. The server walks the ghost chunks for this connection, computes a priority for each one, and sorts the whole list descending before writing anything. That order is what makes the cut meaningful. If it wrote in arbitrary order and stopped when full, the packet would carry a random sample. Because it sorts first, the packet carries the most important prefix, and whatever fell off the end keeps ageing so its priority climbs for next time.
