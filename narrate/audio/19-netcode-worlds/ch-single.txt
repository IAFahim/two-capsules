There is a shape where it is true, and it is worth knowing so you can recognise it when you read package code. A single world host builds one world with both flags set at once, so the client half and the server half share an entity manager and never touch a socket. It is guarded behind an experimental define and a configuration setting, and it is off here. But netcode is full of branches that check for it, and those branches are the reason a comment saying our topology is not a host world is a load bearing comment, not a note.
