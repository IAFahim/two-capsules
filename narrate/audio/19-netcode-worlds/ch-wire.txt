Even in one process, the two worlds do not read each other's memory. The server binds a port and listens. The client connects. Netcode registers two transports for this: a shared memory transport for the pair inside one process, and a real socket for everyone else, including a second editor instance on the same machine. That is why the server row in the tools window shows two endpoints. The in-process pair takes the fast path, and it is still a connection, with an identifier, a state machine, and a disconnect reason.
