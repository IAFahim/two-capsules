The classic mistake is putting the attribute on the method and not on the containing type, which silently does nothing. There is an analyzer for that now, warning number E A zero zero one zero, and its message names the fix. But read the analyzer and you find it deliberately returns without warning for anything implementing the system interface. So the one case a handbook warns you about, a system struct with the attribute on update but not on the struct, is precisely the case that still stays quiet.
