Inside the loop there are exactly two filters left. The version filter compares a stored version number and can skip a whole chunk without touching it, and it has a hard ceiling of two shared values and two changed types, which is a real limit you can hit. Then the switchable component state is two sixty four bit words, one bit per slot. Finding the next entity is count trailing zeros. Advancing past it is clearing the lowest set bit with a single and. If nothing in the chunk is switchable the mask is all ones and the loop is a plain range. That is the entire per entity cost of a query.
