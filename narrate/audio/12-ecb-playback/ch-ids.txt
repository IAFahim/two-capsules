This is the one that overturned something I thought I knew. Folklore says a command buffer create hands you a fake entity with a negative index that gets patched during playback. Read the code and that is not what happens any more. Recording a create allocates real entity identifiers on the spot, from the same global table everything else uses, from inside the job. The documentation says it plainly: the entity is valid immediately, it simply has no chunk until playback puts it in one. There is even a source comment worrying about the atomic contention that costs on some processors.
