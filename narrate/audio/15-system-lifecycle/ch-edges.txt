There is a single stored bit remembering whether the system ran last frame, and it is what turns a level into edges. The first frame the gate is true, that bit is set and the start callback fires once. The first frame the gate goes false after having been true, the engine completes any jobs the system still owns, fires the stop callback once, and clears the bit. It is an edge detector, in the plain hardware sense. Which is why the stop callback is the correct place to release anything the system was holding, and the update callback never is.
